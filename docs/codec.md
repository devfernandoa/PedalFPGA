# 1. Talking to the codec

The DE10-Standard has a Wolfson (now Cirrus Logic) **WM8731** audio codec: a stereo ADC and DAC with a
line input (blue jack), a mic input (pink) and a line/headphone output (green). The FPGA talks to it
over two separate buses:

- **I²C** (control): written once at power-up to set gains, routing, format and sample rate.
- **I²S** (audio): a continuous serial stream of samples in both directions.

Both are in [`codec.vhd`](https://github.com/devfernandoa/PedalFPGA/blob/main/codec.vhd). Before
reading it, build the project and hear it work.

## Build and hear a clean signal

The project needs the HPS system generated by Platform Designer. Part 4 explains what this script does;
for now just run it. Copy `soc_system.qsys` from the GHRD on the Terasic System CD
(`Demonstrations/SoC_FPGA/DE10_Standard_GHRD/`) into the repository, then:

```sh
qsys-script --script=make_soc_system.tcl --search-path="$PWD,$"
qsys-generate soc_system.qsys --synthesis=VERILOG
quartus_sh --flow compile PedalFPGA
```

The compile takes a few minutes and writes `output_files/PedalFPGA.sof`. Program it over JTAG
(Quartus *Programmer* → *Auto Detect* → pick `5CSXFC6D6` → *Change File*, select the `.sof` →
*Start*), or with `quartus_pgm -m jtag -o "p;output_files/PedalFPGA.sof@2"`.

Plug the guitar into the **pink** jack (mic input: it has a +20 dB preamp, which a passive guitar
needs) and the amp or headphones into the **green** one. Out of reset the effect chain is empty and
the input is *line*; you will switch to *mic* from Linux in part 5. Until then use a phone or a
line-level source in the **blue** jack: you should hear it unchanged.

!!! warning "Headphones"
    The output is at line level, which is loud in headphones. Start with the volume of the source low.

## I²C: configuring the codec

The WM8731 has 11 registers of 9 bits. An I²C write is three bytes after the START condition:
the device address (`0x34` = `0011010` + write bit 0), then a 16-bit control word made of the
**7-bit register address** and the **9-bit data**:

```text
 START │ 0011010 0 │ ACK │ R6 R5 R4 R3 R2 R1 R0 D8 │ ACK │ D7 … D0 │ ACK │ STOP
```

`codec_cfg` holds the whole setup as a constant table of control words:

```vhdl
constant WORDS : words_t := (
    x"1E00",   -- R15 reset
    x"0C70",   -- R6  power: oscillator, CLKOUT and outputs off
    x"0117",   -- R0  line in L+R: 0 dB, unmuted
    x"0579",   -- R2  headphone out L+R: 0 dB
    x"0812",   -- R4  analog path: line in -> ADC, DAC -> out, mic muted, no bypass
    x"0A00",   -- R5  digital path: ADC high-pass on, DAC unmuted, no de-emphasis
    x"0E49",   -- R7  format: master, 24-bit, left-justified
    x"1000",   -- R8  sampling: normal mode, 256 fs, 48 kHz
    x"1201",   -- R9  active
    x"0C60");  -- R6  outputs on
```

Read one: `0x0E49` = `0000111 001001001` → register 7 (digital audio interface), data `0x49`:
bit 6 `MS=1` (the codec is the **master**: it generates the bit clock and the frame clocks),
bits 3..2 `IWL=10` (24-bit words), bits 1..0 `FORMAT=01` (left-justified). Check each word against
the register map in the [WM8731 datasheet](https://statics.cirrus.com/pubs/proDatasheet/WM8731_v4.9.pdf).

Three details in that table save you debugging time:

1. **Outputs are powered last.** R6 is written twice: first with the outputs off, at the end with them
   on. Powering the DAC while the rest is still being configured makes a loud pop.
2. **The ADC high-pass is on** (R5 bit 0 = 0). The ADC has a DC offset; the codec's own filter removes
   it, so the effects do not need a DC blocker.
3. **R4 is rewritten at runtime.** When the HPS switches between line and mic, `codec_cfg` sends just
   R4 again (`0x0812` line, `0x0815` mic with +20 dB boost).

The bus itself is a state machine that divides 50 MHz into quarter periods of the 100 kHz SCL clock:
SDA changes only while SCL is low, except for START (SDA falls while SCL is high) and STOP (SDA rises
while SCL is high). The FPGA never drives SDA high: it pulls it low or releases it (`'Z'`) and the
pull-up does the rest, which is how open-drain I²C works:

```vhdl
i2c_sdat <= '0' when sda = '0' else 'Z';
```

If the codec does not acknowledge a byte (NAK), the state machine waits 50 ms and starts over. That
happens right after power-up, while the codec is still waking up.

!!! danger "The I²C bus is shared"
    On the DE10-Standard the codec's I²C lines also go to the ADV7180 video decoder. If the decoder is
    left running it can hold the bus and the codec never gets configured (no sound at all). The top
    level keeps it in reset: `assign TD_RESET_N = 1'b0;` in `PedalFPGA_top.v`.

## Clocking: why 12.288 MHz

The codec's sample rate is derived from its master clock **XCK**, which the FPGA provides. In
"normal" mode with 256 fs (R8 = `0x1000`), the codec divides XCK by 256:

$$ f_s = \frac{f_{XCK}}{256} $$

A tempting shortcut is XCK = 50 MHz / 4 = 12.5 MHz, which gives \(f_s = 48.83\) kHz. Audio still
comes out, but every frequency the pedal computes is off by 1.7 %: the tuner reads about 30 cents
sharp and the delay times are wrong. The fix is a **fractional PLL** that makes exactly
\(256 \times 48\,\text{kHz} = 12.288\) MHz:

```verilog
altera_pll #(
    .fractional_vco_multiplier ("true"),
    .reference_clock_frequency ("50.0 MHz"),
    .output_clock_frequency0   ("12.288000 MHz"),
    ...
) xck_pll (.refclk (CLOCK_50), .outclk (AUD_XCK), ...);
```

## I²S: moving the samples

With the codec as master, it drives three clocks into the FPGA and one data line each way:

| Signal | Direction | Rate | |
|--------|-----------|------|-|
| `AUD_BCLK` | codec → FPGA | XCK/4 = 3.072 MHz | bit clock |
| `AUD_ADCLRCK` | codec → FPGA | 48 kHz | frame clock of the ADC: high = left channel |
| `AUD_DACLRCK` | codec → FPGA | 48 kHz | frame clock of the DAC |
| `AUD_ADCDAT` | codec → FPGA | | ADC samples, MSB first |
| `AUD_DACDAT` | FPGA → codec | | DAC samples, MSB first |

In **left-justified** format the MSB of each word comes in the first bit period after the frame clock
changes:

```text
 LRCK  ‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\_________________________________/‾‾‾
 BCLK  _/‾\_/‾\_/‾\_/‾\_ … _/‾\_/‾\_/‾\_ … _/‾\_/‾\_/‾\_ … _/‾\_/‾\_/‾\_ …
 DATA   │L23│L22│L21│ …  │ L0│ (zero) │    │R23│R22│ …  │ R0│ (zero) │   │L23│
```

The codec changes its data on the falling edge of BCLK and samples DACDAT on the rising edge.

The FPGA does **not** use BCLK as a clock. It samples all four codec signals with the 50 MHz system
clock through two flip-flops (a synchronizer, against metastability) and detects edges:

```vhdl
bclk_s <= bclk_s(1 downto 0) & bclk;            -- shift register, every 50 MHz cycle
rise   <= bclk_s(1) and not bclk_s(2);          -- BCLK went 0 -> 1
fall   <= bclk_s(2) and not bclk_s(1);          -- BCLK went 1 -> 0
```

This works because the system clock is much faster than BCLK: 50 / 3.072 ≈ 16 system cycles per bit.
The design then lives in a single clock domain, and no constraints between clocks are needed.

- **Receive:** on every BCLK rising edge, shift ADCDAT into a 24-bit register. A change of LRCK starts a
  new word; after the 24th bit of a *left* word, `rx` is updated and `rx_ready` pulses for one cycle.
  This pulse, 48 000 times a second, is the heartbeat of the whole pedal.
- **Transmit:** two cycles after each BCLK falling edge, load `tx` if LRCK just changed, otherwise shift
  left. Waiting two cycles lets the synchronized LRCK settle and still leaves about 100 ns before the
  codec samples on the rising edge. The same sample goes out on both channels.

The effects work on 16 bits, so `pedal_core` rounds the 24-bit input (adding 128 before dropping the
lowest 8 bits, and saturating the single value that would wrap around) and pads the output back to 24
bits after applying the volume.

## Test it in simulation

`sim/tb_codec.vhd` puts `codec_cfg` and `codec_i2s` against a model of the WM8731's buses. On I²C it
NAKs the very first byte (to exercise the retry), then decodes every write and compares it with the
expected register list. On I²S it plays the master, sends a different 24-bit word in each left frame
(and junk in the right one) and reads DACDAT back.

```sh
python3 sim/test_vhdl.py
```

The codec test runs first and stops at the first wrong value. Without a local `ghdl` the script uses
the `ghdl/ghdl` Docker image, which takes a few minutes the first time.

!!! success "Checkpoint"
    Sound goes through the board unchanged, and `tb_codec` passes.
